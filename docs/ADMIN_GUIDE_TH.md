# คู่มือผู้ดูแลระบบ (Admin Dashboard)

คู่มือนี้สำหรับผู้ดูแลที่จัดการลูกค้า แผน (Plan) และ License ของ GTRP ผ่าน Admin Dashboard หน้าจอแสดงได้ทั้งภาษาไทยและอังกฤษ กดปุ่ม **ไทย / EN** ที่แถบด้านบน (หรือหน้าเข้าสู่ระบบ) เพื่อสลับภาษา ระบบจะจำภาษาที่เลือกไว้ในเบราว์เซอร์นั้น คู่มือนี้อ้างชื่อเมนูและปุ่มตามหน้าจอภาษาอังกฤษ

ทุกการเปลี่ยนแปลงที่สำคัญจะถูกบันทึกใน **Audit log** พร้อมชื่อผู้ทำและเหตุผล และระบบฝั่งเซิร์ฟเวอร์เป็นผู้ตัดสินสิทธิ์จริงเสมอ ปุ่มที่ไม่แสดงบนหน้าจอคือการกระทำที่สถานะปัจจุบันไม่อนุญาต

## 1. เข้าสู่ระบบและ MFA

1. เปิด URL ของระบบ (เช่น `https://license.example.com/`) แล้วกรอกอีเมลและรหัสผ่านผู้ดูแล
2. ครั้งแรกระบบจะให้ลงทะเบียน MFA: คัดลอก secret (หรือ setup link `otpauth://`) ไปเพิ่มในแอป Authenticator แบบกรอกเอง แล้วกรอกรหัส 6 หลักเพื่อยืนยัน
3. ครั้งต่อไปต้องกรอกรหัส 6 หลักทุกครั้ง
4. กรอกรหัสผิดหลายครั้งติดกัน บัญชีจะถูกล็อก 15 นาที

ข้อควรระวัง: ห้ามแชร์บัญชีผู้ดูแล ให้สร้างบัญชีแยกต่อคนด้วย `scripts/create-admin.mjs` (ดู DEPLOYMENT.md) และกด **Sign out** เมื่อใช้เครื่องร่วมกับผู้อื่น

## 2. Overview

แสดงตัวเลขจริงจากฐานข้อมูล: จำนวนลูกค้า, License แยกตามสถานะ, License ที่ใกล้หมดอายุ, การเปิดใช้งาน (activations) แยกตาม Web/MT4/MT5 และเหตุการณ์ล่าสุด ตัวเลขทุกตัวคำนวณ ณ เวลาที่เปิดหน้า ไม่มีตัวเลขสมมติ

## 3. Plans (แผนบริการ)

แต่ละแผนกำหนด:

| ช่อง | ความหมาย |
| --- | --- |
| Code | รหัสแผนแบบ `UPPER_SNAKE_CASE` เช่น `QUANT_PRO` เปลี่ยนภายหลังไม่ได้ |
| Price / Currency / Billing period | ราคา (หน่วยเต็ม ระบบเก็บเป็นสตางค์), สกุลเงิน, รายเดือน / รายปี / ตลอดชีพ |
| Max Web App devices | จำนวนเบราว์เซอร์ที่ใช้ Web App พร้อมกันได้ |
| Max EA activations (MT4 + MT5) | จำนวนการติดตั้ง EA รวมทั้ง MT4 และ MT5 |
| Max trading accounts | จำนวนบัญชีเทรดที่ต่างกัน มีผลเฉพาะเมื่อเปิด "Bind each EA to a trading account" |
| Web App / features | สิทธิ์เข้า Web App และฟีเจอร์ เช่น `advanced_charts`, `smc`, `volume_analysis`, `ea_connector` |
| EA product IDs / MT4 / MT5 | EA ที่ใช้ได้ (เช่น `gtrp_ea`) และแพลตฟอร์มที่อนุญาต |

การแก้ไขแผนมีผลกับ License ทุกใบในแผนนั้นตั้งแต่คำขอถัดไป การลดจำนวนเครื่องไม่ลบเครื่องที่ใช้อยู่ แต่จะไม่ให้เพิ่มเครื่องใหม่จนกว่าจำนวนจะลดลง การเปลี่ยนแผนจาก/เป็น "Lifetime" ทำไม่ได้ ให้สร้างแผนใหม่แทน

**Disable** แผน: ซ่อนจากรายการแผนสาธารณะและห้ามสร้าง License/ซื้อใหม่ License เดิมยังใช้งานได้ตามปกติ

## 4. Customers (ลูกค้า)

* ค้นหาด้วยอีเมลบางส่วนหรือ ID ลูกค้า กรองตามสถานะ
* หน้า **รายละเอียดลูกค้า** แสดง License, เครื่องที่เปิดใช้งาน และประวัติเหตุการณ์
* **Suspend account**: ลูกค้าถูกออกจากระบบทันทีและ License ทุกใบใช้งานไม่ได้จนกว่าจะ **Reactivate account** (ต้องกรอกเหตุผล)
* **Delete account**: ลบข้อมูลส่วนบุคคลแบบถาวร (อีเมลถูกแทนด้วยค่าไม่ระบุตัวตน), เพิกถอน License และเครื่องทั้งหมด ประวัติ audit ยังคงอยู่แต่ไม่มีข้อมูลระบุตัวตน ใช้เมื่อได้รับคำขอลบข้อมูลที่ตรวจสอบตัวตนแล้ว และไม่มีหน้าที่ตามกฎหมายที่ต้องเก็บไว้ **ย้อนกลับไม่ได้**

ลูกค้าต้องสมัครบัญชีเองก่อน (หน้า Web App) ผู้ดูแลไม่สามารถตั้งหรือเปลี่ยนบทบาท (role) ผ่านระบบได้

## 5. Licenses

### สร้าง License

1. หน้า **Licenses** → **New license** (หรือจากหน้าลูกค้า)
2. กรอกอีเมลลูกค้า เลือกแผน วันที่เริ่ม (ว่าง = ตอนนี้) วันหมดอายุ (ตามรอบบิลหรือกำหนดเอง) และ Grace period (ค่าเริ่มต้น 3 วัน)
3. ระบบแสดง **License Key ครั้งเดียว** ในรูปแบบ `GTRP-XXXX-XXXX-XXXX-XXXX` ให้คัดลอกส่งลูกค้าทางช่องทางที่ปลอดภัย ระบบเก็บเฉพาะค่า hash และแสดงต่อไปเพียง 4 ตัวท้าย
4. ถ้าทำ Key หาย ให้ใช้ **Reissue key** (Key เดิมหยุดทำงานทันที ลูกค้าต้องใส่ Key ใหม่ใน EA)

### สถานะและการเปลี่ยนสถานะ

| สถานะ | ความหมาย | ทำอะไรได้ต่อ |
| --- | --- | --- |
| created | สร้างแล้ว ยังไม่เปิดใช้ | Activate, Renew, Revoke |
| active | ใช้งานได้ (อาจอยู่ในช่วง grace หลังหมดอายุ) | Suspend, Revoke, Renew |
| suspended | ระงับชั่วคราว | Reactivate, Revoke, Renew (ต่ออายุแต่ยังระงับอยู่) |
| expired | หมดอายุและพ้น grace แล้ว | Renew, Revoke |
| revoked | เพิกถอนถาวร | ไม่มี (ต้องสร้าง License ใหม่) |

* ทุกการกระทำต้องยืนยันในกล่องข้อความและกรอกเหตุผลอย่างน้อย 3 ตัวอักษร
* **Suspend** มีผลกับ Web App ในคำขอถัดไป และกับ EA ในรอบตรวจถัดไป (ค่าเริ่มต้นไม่เกิน 30 นาที) EA จะหยุด **เปิด order ใหม่** แต่ยังดูแล order ที่เปิดอยู่ (SL/TP/ปิด order) ได้ตามปกติ
* **Revoke** ปิดทุกเครื่องและ Key ใช้ไม่ได้อีก ใช้กรณีทุจริต/ขอคืนเงินถาวร
* **Renew** เพิ่มรอบบิล (นับต่อจากวันหมดอายุเดิมถ้ายังไม่หมด หรือจากวันนี้ถ้าหมดแล้ว) หรือกำหนดวันหมดอายุใหม่เอง
* **Edit** แก้แผน วันที่เริ่ม วันหมดอายุ grace และบันทึกภายใน การเปลี่ยนแปลงทุกช่องถูกบันทึกใน audit

ถ้ามีผู้ดูแลอีกคนแก้ License เดียวกันพร้อมกัน ระบบจะแจ้ง "modified concurrently" ให้กดโหลดใหม่แล้วทำอีกครั้ง

### เครื่องที่เปิดใช้งาน (Activations)

ในหน้ารายละเอียด License หรือเมนู **Activations** (แท็บ Web / MT4 / MT5):

* แสดงชื่อเครื่องที่ลูกค้าตั้ง วันที่เห็นครั้งแรก/ล่าสุด และว่าผูกบัญชีเทรดหรือไม่ (ระบบเก็บเลขบัญชีเป็น hash เท่านั้น)
* **Reset** (revoke activation) เพื่อคืนโควตาเมื่อลูกค้าเปลี่ยนเครื่อง เครื่องเดิมจะถูกปฏิเสธในการตรวจครั้งถัดไป

## 6. Payments

แสดงรายการชำระเงินแบบอ่านอย่างเดียว สถานะ: pending, paid, failed, refunded การเปลี่ยนสถานะเกิดจาก webhook ที่ตรวจลายเซ็นแล้วจากผู้ให้บริการชำระเงินเท่านั้น ผู้ดูแลแก้สถานะเองไม่ได้

* ปัจจุบัน **ยังไม่ได้เชื่อมผู้ให้บริการชำระเงินจริง** ใน staging อาจเปิดผู้ให้บริการจำลอง (mock) เพื่อทดสอบ ซึ่งไม่มีการตัดเงินจริง
* เมื่อมีการคืนเงินหรือ chargeback ระบบจะ **Suspend** License ที่เกี่ยวข้องโดยอัตโนมัติ ให้ผู้ดูแลตรวจสอบแล้วเลือก Reactivate หรือ Revoke
* เหตุการณ์ `payment.rejected` (จำนวนเงิน/สกุลเงินไม่ตรง) และ payment.paid ที่มี `review_reason` ต้องตรวจสอบด้วยตนเอง

## 7. Audit log

กรองตามช่วงเวลา (UTC), ผู้กระทำ, ลูกค้าเป้าหมาย, License และประเภทเหตุการณ์ เช่น `license.suspended`, `activation.failed`, `user.locked`, `payment.refunded` บันทึกนี้แก้ไขหรือลบไม่ได้ และไม่เคยเก็บ License Key, รหัสผ่าน หรือ token

เวลาทั้งหมดในระบบเก็บเป็น UTC หน้าจอแสดงตามเขตเวลาของเบราว์เซอร์

## 8. งานประจำที่แนะนำ

* รายสัปดาห์: ตรวจ License ที่ใกล้หมดอายุ (ตัวกรอง "expiring within"), เหตุการณ์ `user.locked` และ `activation.failed` ที่ผิดปกติ
* ทุกครั้งที่มีการคืนเงิน: ตรวจ License ที่ถูก suspend อัตโนมัติ
* รายเดือน: ทบทวนรายชื่อผู้ดูแล และตรวจว่าทุกคนเปิด MFA
